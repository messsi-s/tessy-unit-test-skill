# 用例完整度复核清单（独立 reviewer 用）

输入：TESSY 导出的 xlsx/csv、执行报告、交付目录。

## 1. 数据结构完整性

- [ ] 每个对象 `Values`：第 1 行变量名与当前接口**完全一致**（无多余、无缺失、无拼写差异）；
- [ ] 第 2 行方向 `i/o` 与 details XML interfaceReport 一致；
- [ ] 数据行：`tcN.M` 编号连续；**没有空单元格**（不校验写 `*none*`）；
- [ ] `Properties` 每个用例有 Name / Description / Specification；编号与 Values 对齐；
- [ ] 普通桩对象：`Stubs` 表每个用例的桩体齐全；高级桩对象：Stubs 应为空、Values 里有 `xxx()` 变量；
- [ ] 多测试步用例：步号连续，且每步都显式给了跨步状态输入。

## 2. 用例内容质量

- [ ] 用例名能看出"测什么"；描述里写了输入与期望依据；
- [ ] 期望值能追溯到源码公式（不是随手填）；
- [ ] 每条分支都有对应用例（与覆盖度复核对齐）；
- [ ] 错误/异常分支（CRC 失败、越界、非法状态、default）都有用例；
- [ ] 没有"永远通过"的用例（如期望值 = 初值但分支实际没执行到）。

## 3. 执行状态

- [ ] 最近一次执行：失败 0、未执行 0（或未执行项有明确原因）；
- [ ] 报告对象数 = 模块可执行对象数；
- [ ] 失败项已修复或已登记原因。

## 4. 交付一致性

- [ ] `cases\<object>.xlsx` 与 TESSY 中当前数据一致（回读导出对比）；
- [ ] README 中的对象数/用例数与实际一致；
- [ ] review 文档存在且结论可复核；
- [ ] 环境改动清单（ini/module.xml/工程文件）有记录，可回退。

## 5. 输出格式（review/completeness_review.md）

```markdown
# 完整度复核

## 结论
- 对象数：N；用例总数：M；执行结果：ok=x / notok=y / notexecuted=z
- 判定：通过 / 需修复（列问题清单）

## 问题清单
| # | 对象/用例 | 问题 | 严重度 | 修复建议 |
|---|---|---|---|---|
| 1 | demo_xxx TC02 | 期望值 85 与源码公式(80)不符 | 高 | 改为 80 |

## 已符合项
- ...
```
